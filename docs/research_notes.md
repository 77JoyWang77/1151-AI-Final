# 相關研究調查與企畫書修訂紀錄

> 2026-10-13 調查。用途：日後修改企畫書、實作或寫報告時參考。
> 企畫書本體見 `proposal.md`；本檔記錄「查到什麼、採用什麼、為什麼沒採用什麼」。

## 一、調查結論（TL;DR）

1. **整體方向正確**：「LLM 分鏡 → diffusion 生圖 → 一致性模組 → VLM 檢查 → 修正」是 2025–2026 年故事視覺化 Agent 的主流架構（MM-StoryAgent、Audit & Repair、CANVAS 都屬這一型）。本專案的辨識度在於**同一設定下的量化比較**，不在提出新方法。
2. **最重要的補強是 copy-paste 問題**：一致性分數高，可能只是照抄參考圖的姿勢與構圖。ViStoryBench 為此專門設了 Copy-Paste Detection 指標。企畫書已加入「構圖多樣性」指標與假設 H4。
3. **人臉類 ID 方法不適合繪本**：InstantID、PuLID、IP-Adapter-FaceID 以及 ViStoryBench 的 CIDS 都依賴人臉特徵（ArcFace／AdaFace／FaceNet），動物與卡通角色會失效。維持 IP-Adapter plus 加 DINOv2 的選擇。
4. **Reflection 可借鏡 Audit & Repair**：讓 VLM 逐項比對屬性清單，而不是只問「像不像」；只有單一屬性錯時，局部 inpainting 比整張重生划算。
5. **可加的低成本對照組**：StoryDiffusion（免訓練、外掛 SDXL）與 `gpt-image-1-mini` 商用參照組（30 張約 0.35 美金），都列為彈性目標。

## 五、實務數據與經驗（可信度標註）

- **SDXL LoRA 在 Colab T4**：官方 `train_dreambooth_lora_sdxl.py` 加 `--gradient_checkpointing --use_8bit_adam --mixed_precision=fp16`（以及 xformers）可在 16GB 內訓練，但多篇教學都說「勉強跑得動」。〔多個教學來源，可信度中〕
- **IP-Adapter scale**：社群經驗以 0.6–0.7 為一致性與可控性的平衡點；有一篇部落格做了 600 格評估，IP-Adapter（0.65）的同角色通過率 84%，LoRA 為 78%，但底模是 FLUX Kontext、評估是人工判斷。〔單篇部落格，可信度低，只當起點〕
- **`gpt-image-1-mini` 價格**：1024×1024 為 low 0.005／medium 0.011／high 0.036 美金。〔第三方整理，使用前到 OpenAI 官方價目表確認〕
- **CLIP-I 的弱點**：對外觀相近的不同角色區分力差；DINO 較著重主體本身，更適合衡量身分一致性。〔多篇論文的共同說法〕

## 七、自家實驗觀察（2026-10-13～14，目測，待評估指標量化）

> 設定：SDXL base 1.0、DPM++ 2M Karras、30 步、CFG 6.5、1024²；5 份凍結分鏡共 30 格；seed = 故事 × 100 + 格數。

**方案 A（prompt only）**

- 單色系動物角色（小熊、小狐狸）光靠 prompt 就相當一致；多色外觀的人類角色（故事 1、3）有**屬性綁定錯置**：顏色在帽子、泳裝、雨衣、雨靴之間互換（CLIP attribute binding）。
- 人類角色的**臉每格不同**（年齡、臉型、膚色）：外觀 tags 只描述髮型與服裝，沒有定義臉，seed 不同就是不同的人。
- 同一故事內**畫風會漂移**：每格的光線與場景詞（sunset、golden light）把畫風拉往不同方向。
- 劇情關鍵物件常漏畫（沙堡、青蛙、倒麵糊），且有劇情邏輯錯誤（「帽子遺失」卻戴著帽子）；shot_type 幾乎被忽略。
- 畫風比較（2 格 × 7 種）：水彩系較常漏畫具體物件，色塊明確的畫風（gouache、flat vector、crayon）較會畫出沙堡。樣本極少，只作傾向。最終選 gouache。

**方案 B（IP-Adapter plus ViT-H）**

- scale 0.3 時 5 篇的臉、服裝、畫風都明顯一致，是 A → B 最大的改善；畫風統一是**混淆變因**，需另量畫風一致性。
- scale 取捨（印證 H4）：0.2 保留較多劇情但服裝顏色仍會漂；0.3 平衡；0.4 起構圖趨同；0.5 起每格照抄參考圖站姿與背景；0.7 六格近乎同一張。
- **參考圖會被整體照抄**，不只角色：
  - 構圖：半身參考圖 → 每格變半身特寫（故事 1）；側身參考圖 → scale 高時每格側身走路（故事 3）。
  - 背景：有場景的參考圖 → 每格被拉回該場景；**連素色的粉紅底色都會擴散**（故事 5 戶外月夜變粉紅背景）。
  - 顏色：參考圖顏色壓過 prompt，顏色錯的參考圖造成「一致地錯」（故事 2 參考圖是紅吊帶褲，6 格都紅吊帶褲，與描述的藍吊帶褲矛盾）。
  - 姿勢：站姿參考圖讓「躺在床上」變成坐著（故事 5）。
- 參考圖候選本身也有屬性綁定問題：多色外觀的人類 8 張候選中常無一完全正確。
- **參考圖挑選規則（固定優先序，報告需寫明以利重現）**：① 屬性正確 → ② 白或淺灰素色背景 → ③ 正面全身、中性站姿。依此規則建議重選：故事 1 → #5、故事 2 → #5、故事 3 → #6（首輪實際用 6／7／5／8／8）。

**對評估設計的影響**

- 一致性指標必須搭配**構圖多樣性**與**參考圖 copy-paste** 指標，否則 scale 越高分數越好，會誤判。
- 圖文對齊需涵蓋「劇情物件是否出現」，CLIP score 對漏畫小物件不敏感，需 GPT 看圖補足。
- 建議新增**畫風一致性**指標，與角色一致性分開。

### 7.1 評估數據（2026-10-14，`scripts/run_eval.py`，CPU）

> 指標：角色一致性 = Grounding DINO 裁主角 → DINOv2 兩兩 cosine；CLIP score = CLIP ViT-B/32 對該格 image_prompt；構圖多樣性 = 整張圖兩兩 DreamSim（dino_vitb16）距離；參考圖照抄 = 每格與參考圖的 DreamSim 相似度。原始數字：`outputs/eval/*.csv`。

**A vs B@0.3（5 篇）**

| 指標 | A | B@0.3 | 變化 | 方向一致 |
| --- | --- | --- | --- | --- |
| 角色一致性 ↑ | 0.544 | 0.689 | +0.145（+27%） | 5/5 提升 |
| 與參考圖相似 ↑ | 0.561 | 0.680 | +0.119 | 4/5 提升 |
| CLIP score ↑ | 32.12 | 29.36 | −2.75（−8.6%） | 5/5 下降 |
| 構圖多樣性 ↑ | 0.334 | 0.206 | −0.128（−38%） | 5/5 下降 |
| 參考圖照抄 ↓ | — | 0.804 | — | — |

解讀：一致性 +27% 的代價是對齊 −9%、多樣性 −38%；多樣性降幅大於一致性升幅，表示 B 的「一致」有相當部分來自整張畫面趨同，而非只有角色。故事 5 提升最大（0.409 → 0.739，與目測「臉最一致」吻合），故事 3 最小（0.381 → 0.448）。

**scale 掃描（故事 1、3，同一參考圖；一致性／CLIP／多樣性／照抄）**

| scale | 故事 1 | 故事 3 |
| --- | --- | --- |
| A | 0.597 / 29.3 / 0.295 / — | 0.381 / 33.0 / 0.373 / — |
| 0.2 | 0.569 / 27.4 / 0.242 / 0.794 | 0.354 / 33.8 / 0.308 / 0.695 |
| 0.3 | 0.750 / 25.9 / 0.137 / 0.873 | 0.448 / 32.4 / 0.257 / 0.751 |
| 0.4 | 0.786 / 25.9 / 0.117 / 0.881 | 0.511 / 32.3 / 0.244 / 0.788 |

- H4 獲數據支持：scale ↑ → 照抄 ↑、多樣性 ↓，兩篇皆單調。
- 0.2 幾乎無效：一致性不升反略降，但多樣性已開始下降（只付代價）。
- 維持 0.3 為主實驗 scale：0.4 一致性再升但多樣性與 CLIP 續降，故事 1 在 0.3 多樣性已僅 0.137。

**指標限制**

- 角色一致性受背景影響：裁切框含背景 → 已以 SAM 去背改進，見 7.2。
- 偵測率全為 1.0：Grounding DINO 每格都框到東西，但未逐張確認框的是主角，需人工抽查。
- 「方案平均」只在相同故事集合間可比（0.2／0.4 只有故事 1、3）。
- 僅 5 篇：看效果量與方向一致性，不做顯著性檢定。

### 7.2 去背後的角色一致性（Grounding DINO 框 → SAM 分割 → 背景填中性灰 → DINOv2）

89 張全部分割成功；抽查故事 3、5 的 24 張去背結果，切出的都是主角本人（故事 3 的小貓未被切入）。

| 故事 | A 框裁切 → 去背 | B@0.3 框裁切 → 去背 | 去背後 B − A |
| --- | --- | --- | --- |
| 1 | 0.597 → 0.551 | 0.750 → 0.781 | +0.230 |
| 2 | 0.655 → 0.641 | 0.761 → 0.760 | +0.119 |
| 3 | 0.381 → 0.571 | 0.448 → 0.517 | −0.054 |
| 4 | 0.677 → 0.696 | 0.746 → 0.752 | +0.056 |
| 5 | 0.409 → 0.403 | 0.739 → 0.776 | +0.373 |
| 平均 | 0.544 → 0.572 | 0.689 → 0.717 | +0.145（+25%） |

- **主結論不變**：去背後 B 仍比 A 高 0.145，與框裁切版的差距幾乎相同 → IP-Adapter 的提升來自角色本身，不是照抄背景的假象。
- **逐篇結論修正**：故事 3 去背後反轉（A 比 B 高）。A 每格街景不同，拉低了框裁切分數（0.381）；去背後可見 A 的男孩本來就相當一致（0.571）。框裁切版會在背景變化大時**低估 A**。提升篇數由 5/5 修正為 4/5，較可信。
- **效果最大的是臉未被定義的人類角色**（故事 5 +0.373、故事 1 +0.230）；動物角色（故事 2、4）原本就一致，提升空間小。

- **報告以去背版為主指標**；框裁切版放附錄，說明背景對分數的影響。

### 7.3 Reflection 看圖檢查（`scripts/run_reflect.py`，2026-10-14）

設計：GPT 只回報事實（外觀屬性逐項 match／mismatch／not_visible；2–4 個關鍵元素 present／absent／cannot_tell 並標類型 object／action／character／expression；問題限五類），由 `reflect.decide()` 依規則決定 pass／revise_prompt／reseed。

**評審模型選擇與 prompt 迭代**（方案 A 故事 1 六格反覆測試）

- 只用文字規則時，模型常不遵守：把看不到的表情算缺漏、把「看不到」寫進 problems、外觀不符重複寫。
- **用輸出格式強制規則比文字規則有效**：problems 限定五類、元素加上 `cannot_tell` 與 `expression` 類型、程式只把「absent 且非表情」算缺漏後，誤判大幅減少。
- 欄位最前面加 `description`（先描述畫面再檢查）能減少視覺誤判。
- `gpt-4.1-mini` 連續三次漏看畫得很清楚的大螃蟹，且誤用 problems 類型；`gpt-4.1` 正確。改用 gpt-4.1（每格約 0.009 美金，60 格 0.46 美金），並設 temperature=0。

**結果（gpt-4.1，各 30 格）**：A → pass 15、revise_prompt 13、reseed 2；B@0.3 → pass 12、revise_prompt 16、reseed 2。B 的劇情元素缺漏較多，與 B 的 CLIP score 較低一致；故事 5 在 B 有 3 格缺動作，對應「每格正面站姿、粉紅背景」的照抄現象。

**評審可靠度（對照圖片抽查 36 格：A 故事 2–4、B 故事 2、4、5；由 Claude 判斷，非正式人工評估）**

- 動作判斷合理 34/36（94%）。錯誤：A 故事 3 第 1 格把雨傘顏色差異當缺漏（違反規則）；B 故事 5 第 6 格「躺在床上」畫成坐著卻判 pass。
- 強項：劇情物件與動作缺漏（青蛙、蝴蝶、帽子掛樹枝、倒麵糊、抱小貓）抓得準、少誤報 → 補足 CLIP score 的盲點。
- 盲點：劇情矛盾（「帽子不見了」卻綁著頭巾）、角色重複（兩隻小貓）、外觀屬性（B 故事 2 六格都是紅吊帶褲卻未標 mismatch，疑似被畫面中「一致」的角色誤導）。外觀一致性應以角色一致性指標為準，而非 GPT。
- 企畫書規劃的人工抽查 32 張仍需由使用者執行，以計算 GPT 與人的一致率。
